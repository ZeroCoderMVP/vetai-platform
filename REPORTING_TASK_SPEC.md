# Техническое Задание: Интеграция реальных данных и Экспорт в Модуле Отчетности

## 1. Цель
Отказ от mock-данных в модуле отчетности (правило AGENTS.md "No mock by default"). Необходимо научить систему генерировать как минимум один функциональный сводный отчет (например, «Управленческий: Сводка по стаду» — `MGMT-HERD`) на основе реальных данных из базы SQLite, а также реализовать реальный экспорт этого отчета в файл (Excel/CSV) по нажатию кнопки.

## 2. Скоуп работ (Scope)

### Часть 1: Генерация отчета на реальных данных (Backend)
**Где:** `src/lib/services/reporting/report-generator.service.ts`

- Выбрать целевой шаблон, например `MGMT-HERD` (Сводка по стаду).
- В методе генерации (ветка `MANAGEMENT` или `buildManagementReport`) заменить хардкод.
- Реализовать агрегацию через `prisma`:
  - Подсчет общего поголовья (`prisma.animal.count({ where: { farmId, isActive: true } })`).
  - Подсчет дойных, сухостойных, молодняка (через фильтрацию по статусам или группам).
  - Динамика выбытия/поступления в заданный период `periodStart` — `periodEnd` (через `prisma.event`).
- Записывать собранные метрики в поля `payloadJson` и `summaryJson` экземпляра отчета (`ReportInstance`).

### Часть 2: Настоящий экспорт файла (Backend)
**Где:** `src/lib/services/reporting/report-export.service.ts` и `src/app/api/reporting/reports/[id]/export/route.ts`

- Заменить mock-строку генерации URL (в духе `https://storage.../report.pdf`).
- Реализовать преобразование `payloadJson` инстанса в реальный формат:
  - Формирование `.csv` строки или генерация Excel файла (например, с использованием библиотеки `xlsx` или простейшего CSV-билдера).
  - Запись полученного файла локально во временную директорию (например, `/public/exports/` или выдача потоком напрямую через Response API).
- Обновить статус `ReportExportJob` на `COMPLETED` и привязать реальный URL скачивания или Base64 содержимого к объекту экспорта.

### Часть 3: Подключение Frontend-интерфейса (Frontend)
**Где:** `src/app/reporting/reports/[id]/page.tsx`

- Удалить `setTimeout` и заглушки для симуляции загрузки. На старте компонента делать полноценный `GET /api/reporting/instances/[id]`.
- Отрисовывать таблицу и сводку (`summaryJson`), полученные от сервера.
- **Кнопка «Сгенерировать»**: Должна отправлять POST-запрос, дожидаться ответа сервера и обновлять состояние страницы реальными данными.
- **Кнопка «Экспорт»**: Должна инициировать генерацию файла на бэкенде, получать ссылку/blob в ответ и триггерить скачивание файла браузером. Добавить UI-индикацию (спиннер) на время экспорта.

## 3. Требования к качеству (Definition of Done)
1. **Отсутствие фейковых задержек**: Вся логика опирается на реальное время ответа БД и API.
2. **Точность данных**: Цифры в отчете (допустим, количество коров = 1250) доказуемо совпадают с реальным содержимым таблицы `Animal` в SQLite.
3. **Файловый результат**: При нажатии "Экспорт в CSV" в браузере скачивается файл `report_MGMT-HERD_2026-03-XX.csv` с корректно размеченными строками из отчета.
4. **Безопасность UI**: Кнопка экспорта неактивна (disabled), пока отчет не сгенерирован или находится в статусе черновика (`DRAFT`).
5. **Тестируемость**: Весь пайплайн (Создать -> Сгенерировать -> Экспорт) можно пройти без ошибок (сервер возвращает 200 OK, файл скачивается) при локальном запуске `npm run dev`.
