Вопросы тестировщику с обязательными доказательствами
1. Среда и версия

На какой ветке, коммите и сборке проводилось тестирование?
Доказательство: hash коммита, название ветки, вывод git rev-parse HEAD, дата теста.

Какая база использовалась при тестировании: новая, старая, пустая, частично заполненная?
Доказательство: путь к SQLite-файлу, размер файла, дата изменения, краткое описание содержимого.

Какие переменные окружения были выставлены?
Доказательство: список используемых .env-параметров без секретов, особенно DATABASE_URL, VETAI_DB_PATH, VETAI_DATA_ROOT, VETAI_ALLOW_MOCK.

Были ли применены миграции перед тестом?
Доказательство: вывод npx prisma migrate status или иной подтверждённый способ.

2. Проверка запуска приложения

Приложение действительно стартует без ошибок?
Доказательство: вывод npm run dev или npm run build && npm run start, плюс скрин главной страницы.

Есть ли ошибки в консоли браузера при открытии основных экранов?
Доказательство: скрин Console для каждого основного экрана MVP.

Есть ли ошибки на сервере при открытии основных экранов?
Доказательство: фрагмент server log с моментом открытия экранов.

3. Проверка ingestion pipeline

Запускался ли npm run import:afimilk отдельно?
Доказательство: полный вывод команды, список файлов до и после в data/inbox/afimilk, data/processed/afimilk, data/error/afimilk.

Запускался ли npm run import:dtm отдельно?
Доказательство: полный вывод команды, список файлов до и после в соответствующих папках.

Запускался ли npm run import:aic отдельно?
Доказательство: полный вывод команды, список файлов до и после в соответствующих папках.

Запускался ли npm run import:all на полном наборе файлов?
Доказательство: полный вывод команды и итоговое распределение файлов по processed и error.

Для каждого источника реально ли файл переносится из inbox в processed после успешной обработки?
Доказательство: список файлов до/после и хотя бы один пример на каждый источник.

Для каждого источника реально ли ошибочный файл попадает в error?
Доказательство: пример хотя бы одного ошибочного файла на каждый тип ошибки, с текстом ошибки.

Проверялся ли повторный импорт одного и того же файла?
Доказательство: два запуска подряд и записи в IntegrationBatch, подтверждающие duplicate-handling по fileHash.

Проверялось ли поведение на неподдерживаемых форматах AFI (.DAT, .M00 и т.д.)?
Доказательство: имя файла, итоговый статус, запись в IntegrationBatch.errorMessage, путь в data/error/afimilk.

4. Проверка IntegrationBatch

Создаётся ли запись IntegrationBatch на каждый прогон файла?
Доказательство: SQL-запрос и результат по последним batch.

Заполняются ли поля:

source

filename

fileHash

startedAt

finishedAt

status

recordsRead

recordsInserted

recordsUpdated

recordsSkipped

errorMessage
Доказательство: выборка из таблицы IntegrationBatch по нескольким успешным и ошибочным кейсам.

Проверялся ли корректный status для:

успешного файла

ошибочного файла

дубликата
Доказательство: минимум по одному примеру каждого случая.

Проверялось ли, что fileHash одинаков для повторно поданного того же файла и отличается для изменённого файла?
Доказательство: две записи batch с сопоставлением hash.

5. Проверка данных AFI

Какие именно JSON-файлы AFI успешно импортированы?
Доказательство: список файлов и число созданных/обновлённых записей по каждому.

Какие сущности создаются из AFI: события, коровы, обновление лактации, DIM и т.д.?
Доказательство: SQL-выборка до/после импорта и 2-3 примера конкретных записей.

Проверялось ли, что корова не дублируется при повторном появлении в AFI?
Доказательство: SQL по Cow до и после повторного импорта.

Проверялось ли, что события AFI появляются в UI, а не только в базе?
Доказательство: скрин экрана и соответствующая запись в БД.

Проверялась ли обработка некорректного JSON AFI?
Доказательство: пример файла, ошибка, batch-запись, перемещение файла в error.

6. Проверка данных AIC

Импортируется ли .AIC файл без падения?
Доказательство: вывод команды и запись в IntegrationBatch.

Появляются ли записи в MilkRecord?
Доказательство: SQL-выборка по последним вставленным строкам.

Проверялось ли обновление существующей записи MilkRecord, а не только вставка новой?
Доказательство: пример upsert-сценария, где на повторном импорте запись обновилась.

Проверялось ли, что корова для AIC корректно находится/создаётся?
Доказательство: связка Cow ↔ MilkRecord на конкретном примере.

Проверялась ли логика по 6 значениям надоя, о которой мы договорились?
То есть:

1 / 3 / 5 = средние за предыдущие 10 дней

2 / 4 / 6 = текущие значения по 1/2/3 дойке
Доказательство: показать конкретную строку/файл, распарсенные значения, запись в БД и объяснение, как именно тестировщик это сверял.

Проверялось ли, что дневной итог строится корректно на основе текущих 2/4/6, а не средних 1/3/5?
Доказательство: один ручной расчёт на конкретной корове и сравнение с данными системы.

7. Проверка данных DTM

Какие типы DTM-файлов реально были протестированы:

mix history

ingredient consumption

pen history

pen efficiency

manual weighings
Доказательство: список файлов и тип, который определил парсер.

Для каждого типа DTM-файла куда именно записались данные?
Доказательство: таблица “тип файла → таблица БД → число записей”.

Проверялось ли, что MixBatch реально заполняется?
Доказательство: SQL и 2-3 реальные строки.

Проверялось ли, что IngredientConsumption реально заполняется?
Доказательство: SQL и 2-3 реальные строки.

Проверялось ли, что FeedRecord создаётся для pen history / pen efficiency / manual weighings?
Доказательство: SQL и 2-3 реальные строки по каждому сценарию.

Проверялось ли соответствие чисел в Excel-файле и чисел в SQLite после импорта?
Доказательство: ручная сверка минимум по одному примеру на каждый тип DTM.

Подтверждено ли, что приложение и Prisma используют одну и ту же SQLite-базу?
Доказательство: точный путь к файлу, проверка размера, время модификации, SQL-запрос из этой базы.

Проверялось ли отсутствие рассинхрона между реальной схемой БД и ожидаемой Prisma schema?

IntegrationBatch

FeedRecord

MixBatch

IngredientConsumption

Cow

Event

Проверялось ли наличие обязательных колонок, на которые завязан код?
Доказательство: PRAGMA table_info(...) для:

IntegrationBatch

FeedRecord

MilkRecord

Cow

9. Проверка экранов MVP

Какие экраны MVP фактически были открыты руками?
Доказательство: перечень экранов + по одному скрину каждого.

Проверялась ли главная дашборд-страница на реальных данных, а не на mock?
Доказательство: скрин + подтверждение отключённого mock режима.

Проверялась ли карточка животного на реальных импортированных данных?
Доказательство: скрин карточки + SQL по этой корове.

Проверялась ли карточка группы?
Доказательство: скрин + данные в БД, из которых экран строится.

Проверялась ли карточка секции?
Доказательство: скрин + данные в БД.

Проверялся ли переход:

дашборд → группа

группа → корова

секция → группа/животные

Доказательство: видео или серия скринов с URL.

Проверялись ли графики на экранах MVP?
Доказательство: по каждому графику:

скрин

ручная сверка хотя бы одной точки

Проверялись ли все цветовые статусы и индикаторы, которые заложены в MVP?

10. Проверка логики данных, а не просто загрузки

Проверялось ли, что после импорта цифры на дашборде реально соответствуют данным в БД?
Доказательство: ручная сверка по минимум 5 KPI.

Проверялось ли, что число животных на экране совпадает с числом животных в базе?
Доказательство: скрин и SQL.

Проверялось ли, что события AFI и молочные данные AIC относятся к одной и той же корове корректно?
Доказательство: пример одной коровы с данными из нескольких источников.

Проверялось ли, что DTM-данные корректно отображаются на уровне групп/кормления?
Доказательство: экран + SQL/Excel-сверка.

Проверялось ли, что пустые или частично заполненные файлы не приводят к тихой порче данных?
Доказательство: пример такого файла и итоговое поведение.

11. Проверка ошибок и отказоустойчивости

Что происходит, если в inbox лежит файл неверного расширения?
Доказательство: пример, итог в error, batch-запись.

Что происходит, если файл повреждён?
Доказательство: пример и результат.

Что происходит, если у файла валидное расширение, но невалидное содержимое?
Доказательство: пример и результат.

Что происходит, если база недоступна или повреждена?
Доказательство: хотя бы описанный тестовый сценарий и лог ошибки.

Проверялось ли, что один ошибочный файл не ломает импорт остальных файлов в import:all?
Доказательство: mixed-run, где часть файлов успешна, часть нет.

Проверялось ли, что mock не подменяет реальные данные по умолчанию?
Доказательство: скрин/лог/описание переключения.

Проверялась ли сохранность уже импортированных данных после новых прогонов?
Доказательство: до/после по нескольким таблицам.

Проверялось ли, что новые batch-поля не сломали старые экраны/эндпоинты, читающие IntegrationBatch?
