# Разделение ТЗ на этапы: MVP и «потом»

## 1. Принцип разрезания

Ниже исходное ТЗ разделено на две части:

- **MVP / Этап 1**: то, что имеет смысл делать сейчас на текущем курсе проекта, без переписывания платформы с нуля, без ухода в микросервисную архитектуру, без полноценного RBAC, без video/ML в критическом пути и с опорой на реальные или временно mock-данные в SQLite.
- **Потом / Этап 2+**: то, что ценно, но не должно блокировать запуск Stage 1.

## 2. Что входит в MVP

### 2.1. Базовые технические принципы MVP

- Единая база данных на **SQLite**.
- Все основные API и UI читают данные из **SQLite**.
- Импорт данных через файловый ingestion pipeline из:
  - `./data/inbox/afimilk`
  - `./data/inbox/dtm`
  - `./data/inbox/aic`
- Обработанные файлы уходят в:
  - `./data/processed/{source}`
  - `./data/error/{source}`
- Для демонстрации допускаются **mock-данные**, но mock не должен быть основным режимом работы после появления реальных файлов.
- Визуальная часть делается как web-интерфейс для ПК и планшета, мобильная адаптация допускается в упрощённом виде.

### 2.2. Продуктовый состав MVP

В MVP сохраняются три продуктовых контура, но в урезанном и связанном виде:

#### Продукт А. Аналитическая платформа
В MVP включить:
- главный дашборд «Единый монитор фермы»;
- секцию «Молоко»;
- секцию «Поголовье»;
- секцию «Кормление»;
- секцию «Воспроизводство»;
- виджет «Выполнение плана»;
- виджет «Статистика по молоку»;
- упрощённый виджет «Фокус на рисках» без ML-корреляций;
- базовые KPI-карточки по молоку, стаду, кормлению и воспроизводству.

#### Продукт Б. Система управления стадом
В MVP включить:
- модуль «Структура стада»;
- модуль «Планы работ» в упрощённом виде;
- модуль «Воспроизводство и лактации» в базовом виде;
- модуль «Карточка животного»;
- журнал событий животного;
- базовые отчёты;
- базовую историю перемещений/статусов, если она уже есть в модели данных.

#### Продукт В. Учёт молока
В MVP включить:
- главный экран учёта молока;
- график надоев по дням;
- статистику по приходу/расходу молока;
- ленту операций по молоку;
- аналитику качественных показателей в том объёме, который реально обеспечен данными;
- виджет «Молочная ферма»;
- виджет «Выполнение плана».

## 3. Что переносится на «потом»

### 3.1. Архитектура и платформа
Перенести:
- SaaS в полном виде как отдельную задачу;
- микросервисную архитектуру;
- отдельный общий сервис авторизации;
- полноценный SSO;
- полноценную широкую ролевую модель доступа;
- API-маркетплейс широкого охвата.

### 3.2. Продвинутая аналитика и ML
Перенести:
- ARIMA / Prophet прогнозирование на 1–16 месяцев;
- ML-предикцию заболеваний;
- автоматическую причинно-следственную корреляцию типа «болезни → снижение надоя»;
- автоматические рекомендации «что делать»;
- бенчмаркинг между фермами и холдингами;
- генетическую аналитику.

### 3.3. Продвинутый UX и экосистема
Перенести:
- drag & drop виджетов;
- тёмную/светлую тему как отдельную polish-задачу;
- нативное мобильное приложение с offline;
- Telegram-бот, email-дайджест, SMS, browser push;
- встроенный чат поддержки и видеоуроки как отдельный пласт внедрения.

### 3.4. Функции, зависящие от неподтверждённых данных
Перенести до подтверждения источников и качества данных:
- полный блок экономики и финансовых KPI, если не подтверждены цены, расходы и правила расчёта;
- качественные надбавки/штрафы, если не подтверждены контрактные правила молокозавода;
- микроклимат, банки, страховые и 1С как обязательные коннекторы Stage 1;
- карта фермы с маркерами животных.

## 5. Что именно должно получиться к концу MVP

### 5.1. По данным
- Рабочий ingestion из AFI, DTM, AIC.
- Логирование каждого batch в `IntegrationBatch`.
- Единая модель данных в SQLite.
- Возможность подмешивать mock-данные только для незакрытых кусков демо.

### 5.2. По интерфейсу
- Главный дашборд фермы.
- Экран статистики по молоку.
- Экран учёта молока и журнала операций.
- Экран структуры стада.
- Экран карточки животного.
- Экран базовых планов работ.
- Экран воспроизводства/лактаций.
- Набор базовых отчётов.

### 5.3. По аналитике
- Расчёт базовых KPI по молоку.
- Расчёт базовых KPI по стаду.
- Расчёт базовых KPI по кормлению.
- Базовый риск-мониторинг на событиях и динамике.
- План/факт по надою.

## 6. Что важно зафиксировать отдельно

### 6.1. Гипотеза по AIC / DAY_MILK
Для текущей реализации принять рабочую гипотезу:

- в блоках надоев по 6 значениям:
  - **1 / 3 / 5** — средние значения за предыдущие 10 дней по соответствующим сессиям;
  - **2 / 4 / 6** — текущие значения за сессии 1 / 2 / 3 (утро / день / вечер или дойка 1 / 2 / 3).

Эту гипотезу использовать в mock, в интерпретации данных и в коде, пока не будет подтверждён более точный официальный контракт источника.

### 6.2. Принцип демонстрации
Если часть данных ещё не подтверждена, MVP должен:
- честно показывать реальные данные там, где они есть;
- использовать mock только в отмеченных местах;
- не подменять весь продукт демонстрацией на полностью выдуманной ферме.
