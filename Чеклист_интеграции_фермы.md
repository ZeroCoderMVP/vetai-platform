# Чек-лист Интегратора: Аудит и добыча данных на ферме

Этот документ является руководством для выездного инженера-интегратора ВЕТАИ. Его цель — на месте (на ферме) выяснить ИТ-ландшафт предприятия, оценить качество данных и подтвердить техническую возможность интеграции (IN/OUT) с системами типа AfiFarm, DairyComp 305, DelPro, DTM, Selex, 1C и др.

---

## 1. Базовая ИТ-инфраструктура и Доступ
Перед погружением в данные необходимо понять, как физически и сетевым образом работает ПО фермы.

- [ ] **Доступ к серверам:** Где физически находятся базы данных (локальный сервер в коровнике, облако, сервер в главном офисе)?
- [ ] **Сетевая связность:** Есть ли стабильный интернет на сервере БД? Есть ли белый IP-адрес или возможность поднять VPN/WireGuard до облака ВЕТАИ?
- [ ] **Тип СУБД:** Какая база используется под капотом (MS SQL, PostgreSQL, Firebird, Access)? Есть ли пароль от `sa` / `postgres`?
- [ ] **Доступность API:** Предоставляет ли вендор ПО (например, AfiMilk) официальный REST API или SOAP? 
- [ ] **Резервное копирование:** Как часто делаются бэкапы? Настроены ли они? *(Никаких манипуляций с БД без свежего бэкапа!)*

---

## 2. Экспорт (Чтение данных из системы фермы)
Задача: Понять, как ВЕТАИ сможет **автоматически** забирать факты.

- [ ] **Прямой SQL-доступ (Read-Only):** Можно ли создать пользователя с правами `SELECT` и выгребать данные напрямую?
- [ ] **Планировщик отчетов (Watch Folder):** Умеет ли система автоматически (по расписанию) складывать CSV/XML файлы в сетевую папку (FTP / SMB)?
- [ ] **Выгрузка истории (Historical Data):** Можно ли массово выгрузить ретроспективу за последние 3–5 лет (ремовер базы на пропускную способность и ограничения по строкам)?
- [ ] **Синхронизация справочников (Словари):** Доступны ли для выгрузки справочники причин выбытия, диагнозов, списки лекарств, названия рационов?

---

## 3. Импорт (Запись данных обратно в систему фермы - Writeback)
Задача: Понять, сможет ли ВЕТАИ (Stage 2 Outbox) **создавать и менять** события в сторонней системе.

- [ ] **Официальный API на запись:** Есть ли эндпоинты `POST` / `PUT` для событий (например, запуск, отел, лечение)?
- [ ] **Импорт из файлов (Hot Folder):** Есть ли папка, куда можно положить CSV-файл, и система (например, DelPro) автоматически его "проглотит"?
- [ ] **Разрешено ли изменение/удаление:** Можно ли редактировать или удалять события «задним числом»?
- [ ] **Журнал интеграций (Audit Log):** Как реагирует система на ошибки импорта? Куда ложатся ошибочные файлы?

---

## 4. Разведка Мастер-Данных (Справочник животных)
Необходимо определить, что является **Deduplication Key** (Ключом дедупликации) для связи между системами (например, между DTM и AfiFarm).

- [ ] **Идентификаторы (ID):** Выяснить, какие ID используются.
  - Внутренний системный ID (например, `CowId=4123`)
  - Электронная ушная бирка (RFID)
  - Ошейник / Педометр
  - Фермерский (рабочий) номер (например, `2405`)
- [ ] **Целостность данных (Integrity):** Сопадает ли Инвентарный номер животного в 1С с номером в программе доения? (Зачастую — нет).
- [ ] **Базовые атрибуты:** Выгружаются ли Порода, Пол, Статус (Дойная, Сухостойная, Нетель, Выбракована), Дата рождения, Лактация?

---

## 5. Проверка потоков данных (Ключевые 도мены)

### А. Доильный зал (Waikato, Afi, GEA)
- [ ] **Сырые сессии доения:** Сохраняется ли надой по *каждой сессии* (утро, день, вечер) отдельно? Указан ли номер стойла/места?
- [ ] **Качественные показатели:** Есть ли данные по электропроводности, температуре, SCC (соматике) в разрезе каждого доения?

### Б. Кормление (DTM, Selex, Dinamica Generale)
- [ ] **Справочник рецептов и кормов:** Как называются компоненты (Силос кукурузный, Сенаж)? Есть ли дубликаты?
- [ ] **План раздачи vs Факт раздачи:** Как хранятся задания на загрузку миксера и фактический сброс в секцию?
- [ ] **Сложность привязки (DTM -> Herd):** К чему привязан рацион в DTM — к логической группе или к физическому загону/секции? Совпадают ли названия загонов в DTM с группами в AfiFarm? (Критически важно для сведения кормоконверсии).

### В. События здоровья и движения
- [ ] Переводы животного из группы в группу.
- [ ] Отёлы (один против двойни, мертвый плод, вес теленка, тяжесть).
- [ ] Диагнозы (мастит, кетоз, метрит, хромота) и назначения.
- [ ] Охота и Осеменения (номер семени, ФИО быка).

## 6. Практический тест на ферме (Smoke Tests)
Выездной инженер **лично** проводит следующие тесты за ПК фермы:

1. [ ] **Создать тестовую корову** (например, с номером `999999`) в основном интерфейсе.
2. [ ] **Выгрузить (Export) общий список коров** и найти номер `999999`. Проверить, какие поля выгрузились.
3. [ ] **Добавить событие** (например, Взвешивание или Перемещение) на эту тестовую корову. Отредактировать событие "задним числом" (на 3 дня назад).
4. [ ] Попытаться **создать CSV (или использовать API)** с событием "Осмотр" для этой коровы и импортировать его обратно. Проверить, появилось ли оно в интерфейсе фермерского ПО.
5. [ ] **Сформировать конфликт:** Удалить тестовому животному номер ошейника в ПО. Попытаться залить это изменение API-запросом.
6. [ ] **Удалить тестовую корову** и убедиться, что удаление каскадно очистило ее события, либо она перешла в статус "Архив".

---

## 7. Результат выезда
По завершении аудита интегратор должен заполнить `Architecture Concept` со схемой потоков (например: *«1C забирает данные через промежуточную XML-папку, DTM забираем напрямую из Access БД, а с AfiFarm общаемся через API»*) и передать в отдел разработки VETAI.
