# Бэклог доработок базовых роутов (Inbox, Outbox, Conflicts, Sync)

Опираясь на проанализированные сценарии фермы, концепция маршрутизации (Inbox, Outbox, Conflicts, Sync) является фундаментальной. На данном этапе (Stage 2) необходимо доработать этот слой для обеспечения чистоты потока данных, до того как поверх будет надстроен сложный Task Engine и BI.

## 1. Inbox (Входящие события и валидация)
Текущее состояние: *Простая таблица записей (UNCONFIRMED -> CONFIRMED/REJECTED).*

**Задачи по доработке:**
- [ ] **Режим Inline-редактирования (Edit Mode).** Возможность прямо в Inbox заполнить пустое поле `cowId` (если сканер его не распознал) или исправить опечатку перед нажатием `Approve`.
- [ ] **Управление Writeback (Sync Checkbox).** Галочка "Вернуть в систему-источник" при подтверждении события, чтобы оно после одобрения уходило в `Outbox`.
- [ ] **Массовые действия (Bulk Actions).** Пакетное подтверждение (Bulk Approve) отфильтрованных строк (например, списка подтвержденных осмотров).

*(Примечание: Управление задачами, исполнителями и цепочками событий перенесено в слои визуализации — см. Бэклог Аналитики и Задач).*

## 2. Conflicts (Центр разрешения конфликтов)
Текущее состояние: *Отображение двух событий по одному ключу `dedupeKey`, выбор победителя.*

**Задачи по доработке:**
- [ ] **Визуализатор расхождений (Diff Viewer).** Подсветка полей, которые отличаются у конфликтующих записей DTM и AfiFarm, чтобы оператор сразу видел суть спора.
- [ ] **Инструмент слияния коров (Identity Merge).** Интерфейс для объединения профилей животного, имеющего разные ID в разных системах, с переносом истории на мастер-ID.
- [ ] **Комбайн событий (Event Merge).** Слияние двух частично правильных событий (например, Afi дал точное время, а ручной ввод дал препарат) в одну гибридную запись.
- [ ] **Обязательный комментарий разрешения (Resolution Note).** Поле "Почему?" при ручном разрешении спора для сохранения аудитного следа.
- [ ] **Правила автоматического разрешения (Source Truth Rules).** Настройки на уровне системы: "Для рациона приоритет DTM выше AfiFarm", чтобы разгрузить оператора.

## 3. Outbox (Исходящие и Writeback)
Текущее состояние: *Очередь сообщений со статусами UNSENT -> ACKNOWLEDGED / FAILED.*

**Задачи по доработке:**
- [ ] **Механизм автоматических повторов (Retry Engine).** Автоматические повторные попытки отправки с экспоненциальной задержкой при проблемах с сетью.
- [ ] **Ручной перезапуск (Manual Retry & Cancel).** Кнопки "Retry All Failed" и "Отменить отправку" (Cancel) для застрявших пакетов.
- [ ] **Детальный журнал ошибок (Verbose Error Log).** Вывод понятной причины отказа внешнего API прямо в UI вместо сырого JSON.
- [ ] **Приоритеты очередей (QoS).** Разделение трафика: Health-события отправляются немедленно, статистика доения — батчами ночью.
- [ ] **Валидация перед отправкой (Pre-flight Validation).** Проверка обязательных полей внешней системы до постановки в очередь.

## 4. Sync Center (Автоинтеграция)
Текущее состояние: *Запуск API-коннекторов, вывод даты последнего обновления.*

**Задачи по доработке:**
- [ ] **Аудит-лог интеграций (Integration Audit Trail).** Вывод метрик батча: "Получено 150 -> Создано 90 -> Найдено 10 дублей -> Упало в конфликты 50".
- [ ] **Кнопка отката батча (Undo Batch).** Инструмент для мягкого скрытия / удаления загруженного пакета, если источник прислал кривой файл.
- [ ] **Тумблеры управления (Connector Toggles).** Переключатели ручного отключения потоков данных на период технических работ.
