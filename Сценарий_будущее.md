Ты работаешь внутри существующего проекта платформы ВЕТАИ. Твоя задача — спроектировать и реализовать новый модуль сценарного управления хозяйством, который позволит руководителю менять параметры фермы и смотреть прогноз влияния изменений на бизнес и производственные показатели на горизонте 1, 3, 6 и 12 месяцев.

Главная идея модуля:
это интерактивное “управление будущим” для молочной фермы. Пользователь должен иметь возможность создать сценарий, изменить параметры кормления, структуры групп, воспроизводства, экономики, а в архитектуре также предусмотреть генетику и здоровье, после чего система должна пересчитать ключевые KPI и показать, как эти изменения повлияют на хозяйство.

Работай аккуратно, поэтапно, не ломай текущую архитектуру проекта, переиспользуй существующие компоненты, стили, типы и паттерны, если они уже есть. Если Prisma/DB недоступна, обязательно используй mock fallback. Новый модуль должен выглядеть как естественная часть платформы ВЕТАИ, а не как отдельное приложение.

Что нужно реализовать

1. Создать новый раздел в платформе:
- новый пункт в sidebar: “Сценарии” или “Управление будущим”
- новый маршрут: /scenarios или /future-control
- страница должна открываться и работать автономно без обязательной БД

2. Реализовать сущность сценария:
создай типизированную модель сценария, например:
- id
- name
- description
- createdAt
- updatedAt
- timeHorizon
- parameters
- forecastResults
- comparisonToBaseline

3. Реализовать baseline state:
нужно собрать текущее базовое состояние хозяйства из mock-данных или текущих dashboard-данных:
- общее поголовье
- дойные коровы
- группы
- кормление
- здоровье
- воспроизводство
- экономика
Если нужных данных нет, расширь mockData.ts и добавь недостающие realistic mock values.

4. Реализовать сценарный движок:
создай отдельный модуль, например scenarioEngine.ts, который принимает:
- baseline state
- scenario parameters
- selected horizon (1/3/6/12 months)
и возвращает:
- forecasted KPI cards
- chart data
- comparison to baseline
- explanation insights

Важно:
не используй ML и внешние сервисы;
сделай deterministic scenario engine на правилах и коэффициентах;
логика должна быть реалистичной, но не избыточно сложной;
расчет можно делать с месячным шагом.

5. Реализовать параметры сценария

Нужно поддержать такие блоки параметров:

A. Кормление
- изменение цены ингредиентов
- изменение состава рациона
- изменение доли ингредиентов
- изменение dry matter / сухого вещества
- изменение точности кормления
- изменение уровня остатков
- изменение стоимости рациона
Эти параметры должны влиять на:
- стоимость кормления
- кормовую эффективность
- надой
- income over feed / доход минус корм
- риск ухудшения при агрессивных изменениях

B. Группы
- изменение количества животных в группах
- перераспределение по группам
- изменение параметров высокоудойных / среднеудойных / новотельных / сухостойных / транзитных групп
- изменение stocking density / плотности
Влияние:
- структура стада
- распределение надоя
- загрузка помещений
- потребность в кормах
- продуктивность

C. Воспроизводство
- conception rate
- heat detection
- age at first insemination
- voluntary waiting period
- calving interval target
Влияние:
- число стельных
- число отелов
- число новотельных
- лактационная структура
- сервис-период
- экономика

D. Экономика
- milk price
- feed cost index
- vet cost index
- replacement cost
Влияние:
- выручка
- себестоимость литра
- доход минус корм
- общий экономический эффект

E. Архитектурно предусмотреть, даже если частично реализуешь позже:
- genetics
- health

Верхняя панель:

Центральная часть:

- график сравнения baseline vs scenario

8. Реализовать realistic mock behavior
Результаты должны быть правдоподобными.
Нельзя допускать абсурдных скачков.
Используй ограниченные диапазоны влияния.

Примеры логики:
- рост энергетической плотности рациона умеренно повышает надой, но повышает cost/head
- рост точности кормления улучшает feed efficiency и slightly improves IOFC
- рост conception rate не мгновенно меняет всю систему, а постепенно влияет на структуру стада
- изменение reproduction сильнее видно на 3–12 месяцах, чем на 1 месяце
- отрицательные сценарии тоже должны быть возможны
- влияние genetics должно быть delayed, если добавляешь каркас

9. Реализовать explanation layer
После расчета сценария нужно формировать 3–6 кратких explainability insights.
Примеры:
- “Рост дохода минус корм обеспечен повышением точности кормления”
- “Снижение маржи связано с увеличением стоимости концентратов”
- “Эффект воспроизводства становится заметным после 3-го месяца”
- “Основной риск сценария — рост себестоимости рациона”
Сделай это rule-based, без LLM внутри модуля.

10. Реализовать хранение сценариев
Если нет backend persistence:
- используй localStorage или mock repository
- поддержи создание, редактирование, сохранение, выбор сценариев
Если в проекте уже есть mock API pattern, следуй ему.

11. Встроиться в текущую архитектуру
Перед началом:
- изучи структуру проекта
- найди sidebar, mockData, dashboard data sources, API routes, shared UI components, chart components
- используй существующий дизайн и типографику
- если есть уже готовые card/table/chart компоненты, переиспользуй их
- не создавай визуально чужеродный интерфейс

Минимальная логика расчета по блокам

Сделай упрощенную модель:

feeding:
- rationCostDelta -> напрямую влияет на feedCostPerHead
- feedingAccuracy -> влияет на feed efficiency и частично на milk
- refusals -> влияет на потери и эффективность
- dryMatter/energy change -> влияет на average milk в пределах разумных лимитов

groups:
- regrouping/high group optimization -> перераспределяет milk output and feed usage
- stocking density increase above norm -> снижает productivity и повышает risk penalty

reproduction:
- conceptionRate/heatDetection -> влияет на pregnancy rate, fresh cows, calving flow
- effect должен быть gradual by months
- short horizon effect weak, longer horizon effect stronger

economics:
- milkPrice -> влияет на revenue
- feedCostIndex -> влияет на cost side
- vetCostIndex -> влияет на OPEX
- replacement cost -> влияет на overall economics

health/genetics:
- если не успеваешь полностью реализовать, создай интерфейсы, дефолтные значения и архитектурные точки расширения

- страница работает без обязательной реальной БД
- визуально модуль соответствует стилю ВЕТАИ
- код расширяемый и пригоден для дальнейшего добавления genetics и health
