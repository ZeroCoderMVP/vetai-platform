# Контракты данных MVP (Data Contracts Mapping)

В этом документе описана связь между визуальными экранами этапа MVP (согласно `Карта_экранов_MVP.md`) и физической структурой базы данных SQLite (на базе `schema.prisma`). Документ служит единым источником правки для бэкенда и фронтенда при наполнении экранов реальными данными.

---

## 1. Экран «Единый монитор фермы» (Дашборд)

| Блок UI | Таблица (Модель Prisma) | Ключевые поля и условия |
|---|---|---|
| **KPI: Молоко (Приход/Расход)** | `MilkRecord`<br>`AfimilkDayMilk` | `yield`, `session`, `source`.<br>Для на 1 ф/к и 1 д/к берётся счётчик коров из `Cow`. |
| **KPI: Поголовье** | `Cow` | Агрегация (count) с группировкой по `status` (active/dry/culled), `lactation` (>0 - дойные, 0 - нетели/телята). Стельные вычисляются из наличия `Event` "стельность" без последующего "аборт / отёл". |
| **KPI: Кормление** | `FeedRecord` | Агрегация по `date`. Поля: `actual`, `planned`, `iofc`, `feedCostPerHead`. |
| **KPI: Воспроизводство** | `Cow`<br>`Event` | `Cow.dim` (avg). `Event` (расчёт сервис-периода и индекса осеменения на базе событий `insemination`, `calving`). |
| **Выполнение плана (Виджет)** | `MetricValue`<br>`MilkRecord` | Сравнение `MetricValue` (исходный план) и суммы `MilkRecord.yield` за текущую дату. |
| **Фокус на рисках (Виджет)** | `Event`<br>`MilkRecord` | `Event`: count по `category` и `severity` за период. `MilkRecord`: тренд `yield` по дням. |

| **Журнал событий (Лента)** | `Event` | Все `Event` по `cowId`, `orderBy: { timestamp: "desc" }`. |

## 6. Экран «Планы работ»

| Блок UI | Таблица (Модель Prisma) | Ключевые поля и условия |
|---|---|---|
| **Вкладки (Лечение, Вакцинация, Расчистка)** | `OperationRequest`<br>`Event` | Запланированные задачи хранятся в `OperationRequest` (статусы `pending`, `in_progress`, `completed`). Либо генерируются на лету как ожидаемые `Event` по протоколам. |
| **Показатели выполнения (%)** | `OperationRequest` | Отношение `status == 'completed'` ко всем задачам за день. |
| **Воспроизводство (Список на осеменение/отел)** | `Cow`<br>`Event` | Расчетные списки: коровы с `dim > X` без осеменения; коров со стельностью `> 270 дней` в список на отёл. |

## Важные примечания для разработки бэкенда:
1. **Mock Fallback**: Данные загружаются из указанных таблиц. Использовать генераторы заглушек только если `count() === 0` или в рамках `VETAI_ALLOW_MOCK=1`.
2. **Историчность**: В MVP историчность перемещений между секциями базируется на записях из таблицы `CowSectionHistory` и списках событий `Event`. 
3. **Удаление/Отбраковка**: Корова не удаляется физически (`DELETE`), а переводится в `Cow.status = 'culled'` / `'dead'`. Все графики и выборки активного поголовья должны содержать `.filter(c => c.status === 'active')`.
