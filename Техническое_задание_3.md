# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Разработка платформы для управления молочной фермой КРС
*(на основе анализа платформы Агроинтеллект)*

## 1. ОБЩЕЕ ОПИСАНИЕ
Разработать платформу из трёх взаимосвязанных продуктов для цифрового управления молочной фермой КРС. Платформа должна обеспечивать аналитику, управление стадом и учёт молока с инфографикой, дашбордами и системой раннего предупреждения рисков.
Три продукта:
Продукт А — «Аналитическая платформа» (аналог «Онлайн-фермы»): система удалённого контроля, аналитики и прогнозирования.
Продукт Б — «Система управления стадом» (аналог «Мусофт»): учёт поголовья, воспроизводства, здоровья, ветеринарии.
Продукт В — «Учёт молока» (аналог одноимённого продукта): учёт надоев, реализации, товарности и качества молока.

## 2. ПРОДУКТ А — АНАЛИТИЧЕСКАЯ ПЛАТФОРМА
### 2.1. Целевые пользователи
Владельцы, управляющие, зоотехники, внешние консультанты-эксперты, кормовые компании, банки, страховые организации.
### 2.2. Источники данных и интеграции
Платформа автоматически собирает данные из внешних систем и формирует единую управленческую картину. Алгоритм интеграции:
Источник → Коннектор → Нормализация → Хранилище → Аналитический движок → Дашборд
Необходимые коннекторы: — Доильный зал (протоколы передачи данных от доильных роботов и залов, в т.ч. DeLaval) — Система управления кормлением (TMR-трекеры, миксеры, кормовые компьютеры) — Система управления стадом (Продукт Б или сторонние — Afimilk, SCR, DeLaval и пр.) — Система определения охоты (датчики активности, педометры) — Бухгалтерия (1С: интеграция через REST API или файловый обмен) — Система микроклимата (датчики температуры, влажности, вентиляции в коровниках)
Алгоритм сбора данных:
Периодический polling каждого источника (настраиваемый интервал: от 5 мин до 24 часа).
Валидация входящих данных (проверка на диапазон, формат, дубли).
Нормализация в единую модель данных.
Сохранение в хранилище с меткой времени и источника.
Запуск расчётных процедур (KPI, отклонения, прогнозы).
Обновление виджетов дашборда.
### 2.3. Главный дашборд — «Единый монитор фермы»
Один экран с секциями, каждая из которых обновляется в реальном времени.
Секция «Молоко» (обновляется ежедневно): — Валовой надой (ручной замер) — числовое значение + дельта за день (зелёная стрелка вверх / красная вниз) — Валовой надой (доильный зал) — числовое значение + дельта — Отклонение в кг между двумя замерами — Отклонение в % между двумя замерами — Надой на 1 фуражную корову (ф/к) — значение + дельта — Надой на 1 дойную корову (д/к) — значение + дельта — Реализация, кг — значение + дельта — Реализация, % — значение + дельта — Ссылка «Смотреть подробнее» — переход к детализации
Алгоритм расчёта отклонений: Δ = Значение_сегодня - Значение_вчера. Если Δ > 0 → зелёный цвет + стрелка вверх. Если Δ < 0 → красный цвет + стрелка вниз. Отображать и абсолютное, и процентное отклонение.
Секция «Поголовье» (обновляется ежедневно): — Всего поголовье — Фуражных коров — Дойных коров всего — Дойных в стаде, % (окрашивается: >85% — зелёный, 70-85% — жёлтый, <70% — красный) — Сухостойных коров всего — Сухостойных в стаде, % (окрашивается аналогично: <12% — зелёный, 12-15% — жёлтый, >15% — красный) — Стельных коров — Нетелей всего — Тёлок всего — Быков
Секция «Кормление» (обновляется ежедневно): — KPI кормления, % — показатель соответствия загруженного рациона плановому — Кормовая себестоимость 1 кг молока общая (₽) — Кормовая себестоимость 1 кг молока ф/к (₽) — Кормовая себестоимость 1 кг молока д/к (₽)
Алгоритм расчёта KPI кормления: KPI = (Факт_загрузка / План_загрузка) × 100%. Если факт отличается от плана более чем на пороговое значение (настраиваемое, по умолчанию 5%), KPI окрашивается красным.
Алгоритм кормовой себестоимости: Кормовая С/С = Σ(Стоимость_компонент × Кол-во_компонент) / Валовой_надой
— IOFC (Income Over Feed Cost): IOFC = (Надой × Цена_молока) - Стоимость_рациона — Потребление СВ (сухого вещества): расчёт на основе данных от системы кормления
Секция «Воспроизводство» (обновляется ежедневно): — Дач. доения (средний день доения по стаду) — Сервис-период — Стельных в стаде, % — Индекс осеменения
### 2.4. Виджет «Выполнение плана»
Визуальный элемент — горизонтальная прогресс-полоса с числовыми индикаторами.
Параметры: План надоя (кг, редактируемый), Факт надоя (кг, рассчитывается автоматически), Выполнение плана (%).
Алгоритм: Выполнение = (Факт / План) × 100%. Дополнительно рассчитывается процент опережения/отставания от графика: Ожидаемое = (План / Дней_в_месяце) × Прошло_дней. Если Факт > Ожидаемое → «X% опережение плана» (зелёный). Если Факт < Ожидаемое → «X% отставание от плана» (красный).
### 2.5. Виджет «Статистика по молоку»
Временные фильтры: «С начала месяца», «1 день», «7 дней», «30 дней», пользовательский период (date-picker).
Блок «Приход»: Надой (кг), Товарное молоко (кг), % товарности. Блок «Расход»: Реализация (кг), % реализации, Выпойка (кг), Утилизация (кг), Прочее (кг).
Три вкладки с графиками: «Надой» (столбчатая диаграмма по дням), «Расход» (столбчатая диаграмма по категориям), «Реализация» (столбчатая диаграмма отгрузок по контрагентам).
Тип графиков: — Столбчатая диаграмма (bar chart): вертикальные полосы по дням, при наведении — всплывающая подсказка (tooltip) с точными значениями. — Два ряда данных в одном столбце: валовой надой (тёмно-синий) и товарное молоко (голубой) в виде сегментов одного столбца. — Прогнозная полоса (серый цвет) для ещё ненаступивших дней.
### 2.6. Виджет «Фокус на рисках»
Комбинированный график (combo chart): — Линия (area chart с заливкой): тренд валового надоя за период — Столбцы (bar chart): количество событий за день
Tooltip при наведении: «Событий всего: N» и детализация — переведено в сухостой, вакцинация, осеменений, расчистка копыт, переведено в группы.
Алгоритм выявления рисков:
Для каждого KPI задаётся допустимый диапазон (настраивается администратором).
При выходе значения за диапазон — генерируется event «Отклонение».
Автоматическая корреляция: если одновременно упал надой и выросло количество больных животных → генерируется предупреждение «Возможная связь: болезни → снижение надоя».
### 2.7. Виджет «Финансовые KPI»
Карточки с крупным числом и подписью: — Стоимость рациона на 1 голову (₽) — цветовая кодировка по отклонению — Валовая прибыль на 1 голову (₽) — Себестоимость молока (₽/кг)
Алгоритмы: — Стоимость_рациона_1гол = Σ(Стоимость_кормов) / Поголовье_фуражных — Валовая_прибыль_1гол = (Выручка_от_молока - Затраты_на_корма) / Поголовье_фуражных — Себестоимость_молока = Затраты_на_корма / Валовой_надой
### 2.8. Мобильная адаптивность
Все дашборды доступны с ПК, планшета и смартфона. На мобильном устройстве — карточки стекаются вертикально, графики адаптируются по ширине экрана, сохраняя интерактивность tooltips.
### 2.9. Прогнозирование (преимущество над конкурентом)
Алгоритм прогнозирования надоя: — На основе исторических данных (ARIMA / Prophet): прогноз на 1-16 месяцев вперёд. — Входные данные: исторический надой, количество дойных коров, структура стада по лактациям, сезонность. — Визуализация: пунктирная линия на графике после текущей даты с зоной неопределённости (confidence interval).
Что добавить лучше конкурента: — Алгоритм ML-предикции заболеваний на основе аномалий в надое, активности, потреблении корма. — Push-уведомления о критических отклонениях (Telegram-бот, email, SMS). — Сравнительная аналитика ферм внутри холдинга (бенчмаркинг).

## 3. ПРОДУКТ Б — СИСТЕМА УПРАВЛЕНИЯ СТАДОМ
### 3.1. Целевые пользователи
Зоотехник, ветеринар, управляющий, владелец.
### 3.2. Модуль «Структура стада»
Визуализация: Столбчатая диаграмма (stacked bar chart) с разбивкой по возрастным/лактационным группам.
Ось X: группы — 0-2 мес., 2-6 мес., 6-12 мес., 12-18 мес., 18+ мес., Лакт. 1, Лакт. 2, Лакт. 3, Лакт. 4+. Ось Y: количество голов. Цветовая кодировка столбцов: Телки (зелёный), Нетели (светло-зелёный), Быки (оранжевый), Дойные (синий), Сухостойные (голубой).
Правая панель — сводная таблица: — Всего голов, 100% — Молодняк: кол-во, %, из них: Тёлки, Нетели, Быки — Фуражные: кол-во, %, из них: Дойные, Сухостойные — Средний номер лактации (расчёт)
Алгоритм расчёта среднего номера лактации: Ср_лактация = Σ(Номер_лактации_i) / Кол-во_фуражных_коров
### 3.3. Модуль «Учёт движения молока»
Экран учёта: шапка с агрегированными данными за день/период. Лента операций: каждая запись — дата, тип операции (надой/реализация/выпойка/утилизация/прочее), ответственный, кол-во кг, качественные показатели (жир, белок, соматика).
Кнопки действий: «Добавить», «Сформировать ведомость». Фильтры: «Тип операции», «Период».
### 3.4. Модуль «Планы работ»
Автоматическое формирование ежедневных рабочих списков.
Вкладки: Лечение, Воспроизводство, Вакцинация, Расчистка копыт. В каждой вкладке: количество задач, % выполнения, цветовой индикатор (красный — 0%, жёлтый — частично, зелёный — 100%).
Внутри вкладки «Лечение»: группировка по локализации — Вымя, Конечности, ЖКТ, Органы воспроизводства, Сердечно-сосудистая система, Органы дыхания, Прочее. У каждой категории — число животных на лечении.
Внутри вкладки «Воспроизводство»: Проверка стельности, Перевод в сухостой, Перевод в поздний сухостой, Планируемые отёлы. Рабочий список на осеменение, на синхронизацию.
Внутри вкладки «Вакцинация»: Плановая вакцинация, Отклонения от плана, Животные без плана вакцинации.
Алгоритм автоформирования планов:
Для воспроизводства: на основе репродуктивного статуса и даты последнего события рассчитывается следующая дата. Например: если корова осеменена N дней назад → поставить в список на проверку стельности через (28-35) дней.
Для вакцинации: на основе протокола вакцинации и даты последней → добавить в план через заданный интервал.
Для расчистки копыт: по параметрам настроек (например, каждые 100-120 дней).
### 3.5. Модуль «Воспроизводство и лактации»
Визуализация цикла оплодотворения: горизонтальная временная шкала со статусами-маркерами: Осеменение → Стельная → Сухостой → Поздний сухостой → Отёл. Каждый статус — цветной кружок (зелёный = пройден, серый = ожидается).
Информация по каждой лактации: номер лактации, начало цикла, конец цикла, длительность (дней), цикл оплодотворения с датой отёла.
Алгоритмы: — Автоматическое определение аборта: если после подтверждённой стельности нет отёла в срок ±15 дней от расчётной даты → флаг «Подозрение на аборт/эмбриональная смертность». — Расчёт индекса осеменения: Индекс = Кол-во_осеменений / Кол-во_стельностей — Расчёт сервис-периода: Сервис_период = Дата_первого_осеменения - Дата_отёла
### 3.6. Модуль «Карточка животного»
Полная карточка на одном экране: Номер, Кличка, Статус (В стаде / Выбыла).
Шапка: Общие данные (репродуктивный статус, номер лактации, день доения, день стельности), Текущая лактация (дата последнего осеменения, дней с осеменения, количество осеменений).
Вкладки: — Основное: порода, дата рождения, вес, родословная — Воспроизводство: история лактаций, осеменений, отёлов, циклы оплодотворения — Надои: график лактационной кривой, контрольные дойки — Здоровье: подвкладки — Диагнозы, Протоколы вакцинации, Расчистка копыт. Добавление диагноза, привязка протокола лечения, история болезней. Каждый диагноз: болезнь, статус (активный/завершён), дата начала, локализация, продолжительность. — Журнал событий: хронологический лог всех действий по животному
### 3.7. Модуль «Отчёты»
Предустановленные отчёты: Отчёт по репродуктивным статусам, Отчёт надоя по группам, Отчёт распределения по группам, Отчёт по эффективности протоколов лечения, Отчёт по эффективности вакцинации. Экспорт в Excel/PDF.
### 3.8. Модуль «Выращивание молодняка»
Фиксация вакцинаций по плану, перебиркование, рабочий список на перемещение телят в зависимости от возраста, рабочие списки на осмотр (взвешивание, замер роста), схема выпойки.
### 3.9. Модуль «Лечение и диагностика»
Справочники: номенклатура лекарственных препаратов (глобальный и для каждой фермы), список болезней, протоколы лечения.
Функции: постановка диагнозов, назначение протоколов лечения, фиксация истории лечения в рамках каждого диагноза, рабочие списки по группам болезней, отчёты по эффективности протоколов.
Алгоритм анализа эффективности протоколов: Для каждого протокола лечения рассчитывается: % выздоровлений, средняя продолжительность лечения, рецидивы. Визуализация — рейтинг протоколов.
Что добавить лучше конкурента: — Интеграция с базой ветеринарных препаратов с автоматической проверкой срока каренции (молоко после лечения антибиотиками). — Автоматический алерт: «Молоко от животного X нельзя отправлять в реализацию до ДД.ММ.ГГГГ». — Визуальная карта фермы с маркерами больных животных.

## 4. ПРОДУКТ В — УЧЁТ МОЛОКА
### 4.1. Целевые пользователи
Зоотехник, бригадир, экономист, управляющий, владелец.
### 4.2. Главный экран
Шапка: Приход (надой, товарное молоко, % товарности), Расход (реализация, выпойка, утилизация, прочее), Доход (₽).
Алгоритм расчёта дохода: Доход = Σ(Реализация_i × Цена_i) с учётом жирности и сорта.
Алгоритм товарности: Товарность = Товарное_молоко / Валовой_надой × 100%
### 4.3. Инфографика: график надоев по дням
Тип: вертикальная столбчатая диаграмма (bar chart), ось X — дни, ось Y — кг.
Два сегмента в каждом столбце: валовой надой (тёмно-синий) и товарное молоко (голубой). При наведении tooltip: дата, день недели, валовой надой (кг), товарное молоко (%, кг), дойных коров (шт), надой на 1 д/к (кг).
Миниатюрная навигационная полоса (scrollbar) внизу — для прокрутки временного периода.
### 4.4. Статистика
Фильтры: «Дворы и группы: все» (dropdown), временной фильтр (с начала месяца / 1 день / 7 дней / 30 дней / пользовательский период).
Агрегированные показатели: Приход (надой, товарное молоко, %), Расход (реализация, %, выпойка, утилизация, прочее), Доход.
Дополнительно: среднесуточный надой, надой на 1 д/к.
Три вкладки графиков: Надой, Расход, Реализация — переключаются и меняют тип столбчатой диаграммы.
### 4.5. Виджет «Молочная ферма»
Правая панель: выбор фермы (dropdown), фуражных голов, дойных голов, остаток молока (кг), дата последних данных.
### 4.6. Виджет «Выполнение плана» (идентичен п. 2.4)
### 4.7. Контроль надоев и движения молока
Лента операций (журнал): — Надой: иконка (синяя +), количество кг, ответственный, дата — Реализация: иконка (красная ₽), -кг, контрагент, качественные показатели (жир, белок, соматические клетки, номер ТТН) — Выпойка: иконка (зелёная), -кг — Утилизация: иконка, -кг
### 4.8. Аналитика качественных показателей
Комбинированный график: — Столбчатая диаграмма надоя (по дням) — Линейный график: жир (%), белок (%), мочевина (мг/дл), соматические клетки (тыс.) — Правая панель: плотность, мочевина, соматика — числовые значения
Табличный вид: столбцы — дата, жир, белок, %, плотность, мочевина, соматика.
Алгоритм расчёта «Качественная надбавка/штраф»: — Если жир > базовой нормы → расчёт надбавки за каждые 0.1%. — Если соматика > порога → штраф в % к цене. — Автоматический расчёт итоговой цены молока с учётом качества.
### 4.9. Аналитика отгрузок и реализации
Таблица/график по контрагентам: рейтинг покупателей по объёму, цене, регулярности.
### 4.10. Особенности
— Не требует длительного обучения. Быстрый старт за 2 минуты. — Работает в браузере, доступен с любого устройства. — Адаптивный дизайн (смартфон, планшет, ПК).
Что добавить лучше конкурента: — Автоматический расчёт прогноза остатков на конец дня/недели. — Интеграция с приёмкой молокозавода (электронный обмен данными по ТТН). — Калькулятор «Оптимальная цена реализации» с учётом качественных показателей и рыночных данных.

## 5. ОБЩИЕ ТРЕБОВАНИЯ
### 5.1. Архитектура
— SaaS-решение, серверная часть на территории РФ — Микросервисная архитектура: отдельные сервисы для каждого продукта + общий сервис авторизации — REST API для интеграций — Единая учётная запись (SSO) для всех трёх продуктов — Ролевая модель доступа: Администратор, Владелец, Управляющий, Зоотехник, Ветеринар, Бригадир, Оператор, Консультант (только чтение)
### 5.2. Технологии визуализации и инфографики
Для всех дашбордов и графиков использовать библиотеку Apache ECharts или D3.js с custom-рендерингом:
— Карточки KPI: крупное число + дельта (со стрелкой и цветом) + подпись — Столбчатые диаграммы: stacked bars, grouped bars, с анимацией при загрузке — Линейные графики: area charts с gradient fill, дефолтный smooth line — Прогресс-бары: горизонтальные, с двухцветной заливкой (факт vs план) — Кольцевые диаграммы (donut): для структуры стада, распределения расходов — Таймлайны: горизонтальные с маркерами статусов (для цикла оплодотворения) — Tooltip: при hover — карточка с полной детализацией, при мобильном — по tap — Цветовая система: красный (отклонение), зелёный (норма/рост), жёлтый (предупреждение), синий/голубой (нейтральные данные)
### 5.3. UX/UI
— Минималистичный дизайн с акцентом на крупные числа и графики — Мультидворовая поддержка: переключатель фермы/двора в правом верхнем углу — Drag & drop виджетов на дашборде (персонализация) — Тёмная/светлая тема — Печать отчётов и экспорт в PDF/Excel
### 5.4. Уведомления
— Push-уведомления в браузере — Telegram-бот с ежедневной сводкой — Email-дайджест (настраиваемая периодичность) — SMS для критических алертов
### 5.5. Процесс внедрения
— Аудит фермы → Настройка интеграций → Миграция данных из старой системы → Обучение персонала → Запуск → Сопровождение — Видеоуроки в системе — Встроенный чат поддержки — Онлайн-документация
### 5.6. Конкурентные преимущества (что сделать лучше)
ML-прогнозирование — предсказание надоя, заболеваний, оптимальных дат осеменения на основе исторических данных.
Автоматические рекомендации — не просто показ отклонений, а конкретные рекомендации по действиям (например: «Снижение надоя у группы Лакт.2 на 5%. Возможная причина — изменение рациона 3 дня назад. Рекомендация: проверить усвояемость нового компонента»).
Карта фермы — визуальная схема расположения групп/дворов с цветовым отображением статусов.
Бенчмаркинг — сравнение фермы с отраслевыми стандартами и другими фермами холдинга.
Мобильное приложение — нативное (не только адаптивный веб), с оффлайн-режимом для ввода данных в полевых условиях.
Каренция — автоматический контроль «молоко от лечёного животного не в реализацию».
Генетическая аналитика — подбор быков-производителей на основе родословной и KPI потомства.
API-маркетплейс — готовые интеграции с максимальным числом систем: Afimilk, DeLaval, Lely, GEA, SCR и др.
