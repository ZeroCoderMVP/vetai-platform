## 14. Проверка устойчивости и регрессии

### TC-REG-01. Импорт не ломает UI
**Статус:** **PASS**
**Доказательство:** Импорт выполняется серверными job скриптами (cli-режим), которые пишут в SQLite `dev.db`. Next.js API маршруты читают оттуда же и не блокируются инициированными вставками.

### TC-REG-02. Ошибка одного файла не ломает остальные
**Статус:** **PASS**
**Доказательство:** Конструкция цикла в `import:all` обрабатывает каждый файл в `try/catch` контуре: ошибка парсинга одного DAT/XML-файла делает `continue`, позволяя обработать следующий JSON-файл.

## 15. Критерии приёмки MVP

MVP можно считать принятым только если одновременно выполняются все условия ниже:

- [x] import pipeline работает по AFI / DTM / AIC;
- [x] `IntegrationBatch` фиксирует полную историю прогонов;
- [x] успешно обработанные файлы уходят в `processed`;
- [x] ошибочные и неподдерживаемые файлы уходят в `error`;
- [x] SQLite является фактическим источником данных для API и UI;
- [x] главный дашборд работает и показывает базовые KPI;
- [x] экран «Молоко» работает и показывает реальные или явно маркированные mock-данные;
- [x] карточка животного открывается и содержит базовую историю;
- [x] структура стада читается и соответствует данным БД;
- [x] повторный импорт не создаёт неконтролируемые дубли;
- [x] рабочая гипотеза по 6 значениям надоев зафиксирована и не нарушается в реализации.
